## 4. SSH 真实执行域端到端（L-02）

**形态申报**：本机无 Docker/WSL 可承载 sshd、Windows OpenSSH Server 安装需管理员权限、已知远端主机未授权本机密钥（BatchMode 实测 Permission denied）——**真 OpenSSH 服务端 / 真 Linux 远端主机仍环境门控**。本次收口采用 **loopback 真 SSH2 协议服务端**（[scripts/smoke-ssh.mts](../../scripts/smoke-ssh.mts)）：ssh2 npm 服务端（密钥交换 / 公钥认证 / exec 通道走真实线上协议）+ 一次性 `ssh-keygen` 密钥对（临时目录即弃，不触碰用户 `~/.ssh`）+ SshExecutor 经**真实 OpenSSH ssh.exe 客户端**连接——客户端与协议层全真，仅「远端主机」由 harness 扮演（收到的 `cd <path> && env … sh -c <cmd>` 经解析后由本机 POSIX sh 执行，与 SshExecutor 远端命令契约同构）。

**断言（5 组全绿，已入 `smoke:p0` 回归链）**：

- A 探针：`resolveSandboxExecutor(ssh 配置)` → `kind=ssh` 无告警（`exit 0` 探测走真实协议）。
- B 回合端到端：mock LLM 脚本化两次 bash 工具调用 → SSH 执行域执行 → 服务端线上核对两次 exec 的 cwd 映射（workspace 根 → `remoteWorkspaceRoot`）+ 远端落盘文件在映射根存在且内容一致（N-3）。
- C env 注入：`SshExecutor.run` 显式 env → 服务端线上核对 env 前缀 + 远端 shell `echo $SMOKE_SSH_PROBE` 可见。
- D 失败收敛：错误密钥 → 探测失败 → 回退 local + 告警（02 §5.4 fail-closed）。
- E 本地审计：SSH 执行域工具调用事件落本地数据根事件流（T3.2「远程执行、本地审计」口径）。

**真实缺陷修复（本次收口的核心价值）**：`SshExecutor.run/spawn` 此前把 argv 数组裸 join 成 shell 命令串——① Windows 反斜杠路径（`-i C:\Users\...`）被 bash 当转义吃掉（`Identity file C:Users15045... not accessible`）；② 远端命令内的 `&&` 被本地 shell 当作命令链截断。m3 的 argv 级断言（`buildArgv`）验证的是 argv 世界，执行走的是 shell 字符串世界——两层必须显式换算。修复：argv join 点统一 shell 单引号包装（bash 与 PowerShell 单引号均为字面语义；单引号转义习语两 shell 不同，按 bash 习语处理，PS 回退属既有申报限制）；既有测试断言同步到新不变量（`ssh '-o' …`），新增注释锁定「argv 世界 → shell 字符串世界」契约。案例归位 defensive-patterns N-5。

**残留申报**：远端命令内嵌双引号经本地 shell 传递会被消耗一层转义（JSON.stringify 的 `\"` → `"`）——含内嵌双引号的远端命令会被改写；POSIX 远端建议后续以 base64 包装加固（M5+ 候选，登记 PROGRESS §5 注记）。
