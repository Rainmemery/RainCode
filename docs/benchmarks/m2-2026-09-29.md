## 3. 测量方式明细（对照 01-PRD §6.1）

- **NFR-1/2/3/5/7**：与 M1 报告 §3 完全同口径（`scripts/bench-lib.mts` 未改动测量逻辑；本轮仅被测对象为 M2 代码基线）。
- **NFR-4**：`scripts/bench-mem-desktop.mts`——spawn electron（dist 产物形态：main.cjs + renderer bundle + agent bundle 子进程），60s 预热后每 30s 采样一次 ×10（= 5 分钟空载窗口），每次采样进程树（electron main + renderer/GPU 子进程 + agent 子进程）WorkingSet64 求和，报中位数与峰值。**口径申报**：以 `Get-CimInstance Win32_Process` WorkingSetSize（与任务管理器「内存」列同源 Win32 数据）替代三进程内嵌 `process.memoryUsage` 打点——Alpha 阶段不在三进程内埋采样端点，外部同源采样含共享页重复计账，口径偏保守（对 ≤500MB 判定方向偏严）。
- **NFR-6**：`packages/server/test/compact-nonblocking.test.ts`——mock LLM 摘要请求延迟 600ms 制造压缩窗口，窗口内 `session.send` 受理耗时与 `tool.tools.list` 探测耗时断言 < 100ms（07 口径「零排队等待」的可执行化），`compact.completed` ok:true 收敛；进程级连续性由 `smoke:compact` 用例 A 承担（已入 `smoke:p0` 回归）。
